# Is state_env_october too strong for test-time scaling? (existing data + CPU only)

Question (Leon, 2026-10-05): Dan says the current models are too strong to study test-time scaling. Can we just
pose out-of-distribution problems? No GPU job was run for this note; every number comes from stored results or
CPU-only analysis. Scripts are in [`ood_check/`](ood_check/); generated sets and raw profiles are in
`/scratch/cowifornia/nd-rl/think/ood_check/`.

## Verdict

- Dan's claim holds for the generator's own pools only: holdout250 239/250 (95.6%), long pool 377/380 (99.2%),
  ≥17 lines 21/21, RL targets 4,369/4,495 (97.2%) at pass@256.
- Sets that need no change to vocabulary or interface already have low pass@1, and success keeps rising with compute:
  - Charles's long problems (>10 lines, n=90): pass@1 7.7-13.0%, pass@256 34.4-46.7%, plus +9.1 pp from guided
    redraws at matched tokens;
  - textbook_dev (n=58, best-state s0 RL): pass@1 40.8%, pass@2048 79.3%;
  - trajectory's group C: pass@256 5.7-14.3%, pass@2560 17.9-27.8%.
- Most "wildly OOD" axes fail on format, which thinking cannot fix:
  - ≥4 premises: the first or second action fails at "PR position"; h4-h8 are never trained;
  - formula depth ≥7: a malformed formula at the first own action;
  - >4 atoms: not expressible;
  - more than about 30 names in scope: names run out;
  - classical schemas: a knowledge gap. Four demonstrations install excluded middle; extra sampling does not.
- The usable OOD axis is structural depth with small formulas: nested case splits and reordering. Failures there
  come deep in the proof (median own step 6-20), and pass@16 is well above pass@1.
- Narrower claim that does hold: sampling-style TTS competes with expert iteration, which already distils pass@k
  into pass@1. So thinking must be judged at matched compute against plain sampling and guided redraws from the
  same base.

## Recommended testbed

- **Tier A: Charles's long problems within reach.** 80 of 90, excluding:
  - ≥4 premises;
  - formula depth 7;
  - name exhaustion;
  - states over 400 tokens.

  The knob is the line bin: 11-20 lines (62), 21-30 (13), 31-51 (5). 27 of the 80 are classical; report them
  separately.
- **Tier B: generated families with bounded formula size.**
  - Three families, generated by `ood_check/gen_ood.py`, with n = 3-8 and 40 items per n (720 items):
    - `or_reorder`: nested Or.elim, then an Or.inl / Or.inr chain;
    - `and_reorder`;
    - `commute`.
  - All reference proofs pass nd_verify and Lean.
  - 0 share a renaming class with K12 ∪ rl_targets.
  - Formula depth ≤4, 1 premise, ≤22 names in scope.
  - Use n ≤ 6: at n = 8, states reach 396 tokens, above K12's maximum of 386.
- **Tier C: hard in-distribution theorems.** Transfer-pool theorems no ladder round solved (113 of 2,285 for s0),
  plus group C. Needs mining.
- **Excluded as TTS testbeds:** ≥4 premises, formula depth ≥7, >4 atoms, more than about 30 names in scope.
  Run classical schemas as a separate teachability track.
- **Context:** per-step states in Tier A are ≤317 tokens and actions ≤99, which leaves ≥600 tokens per step for
  thinking in a 1,024 window. K12 training pairs never exceed 391 tokens, so thinking pretraining must include
  long sequences.
