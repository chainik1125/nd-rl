## Q1. How EDL is defined and computed

- **Online (prequential) code.** BTC Eq. 1 (§2.2): MDL = sum_i l(theta_{i-1}; x_i, y_i), l = -log p(y|x). "In practice, training proceeds by batches. For each batch, we accumulate the total log-loss (summed over all labels in the batch) before the gradient update." So scoring is **score-then-step per batch**; every example is scored with parameters from before its own batch's update. EDLth §3.1 says the same: "all examples in the batch are encoded using the pre-update parameters."
- **Which examples are scored when.** MDL uses the **first epoch only**: "The sum across all labels in the dataset (i.e., in the first epoch) gives the MDL" (§2.2) and footnote 1: "Accumulation over additional epochs would correspond to encoding redundant information". Test loss is "computed using the final trained model (arbitrary epochs)" (§2.5).
- **Residual and termination.** Eq. 2-3 (§2.3): EDL = MDL - n * L_test(theta*), with theta* "after training to some termination condition (e.g., convergence, some number of epochs, or a fixed compute budget)". L_test is the mean loss over a held-out test set "from the same distribution". In the experiments: Table 1 "Stopping criterion: Validation loss convergence"; App. D "we train to convergence in all experiments"; fn. 5 (App. E.1.1): "'Convergence' is determined by maximal performance on the chosen validation metric (either maximization of the validation accuracy or minimization of the validation loss)". The number of epochs actually used is **not reported anywhere**. EDLth §3.2 adds that theta* is "considerate of any early stopping condition" and App. D.2: "maximum EDL can be obtained by training to best achievable performance on the validation set (with early stopping prior to overfitting) and evaluating test loss on the best model checkpoint."
- **Units.** Losses in nats, converted: "we express EDL in bits, by dividing by ln 2" (§2.5; App. F "bits = nats / ln 2"). Raw EDL is a total over the dataset (not per example); normalisations in §2.4 are: per token (EDL/D, D = total label token count), per parameter (EDL/P), and "Capacity, or EDL ratio (EDL(P, D)/EDL_ref(D))". EDLth §3.4 adds per-example EDL/n.
- **Loss mask.** §2.1: "We compute cross-entropy loss only on designated label tokens, typically the answer portion of the output (excluding the prompt and formatting)." App. F: arithmetic: "we score only the numerical answer tokens. The prompt ... and any formatting tokens are excluded from both MDL computation and test loss evaluation." **Reasoning (Qwen): "we score the full response including chain-of-thought reasoning final answer."** (App. F) and App. B: "we score the full reasoning trace plus answer." So the reasoning EDL includes the thinking tokens. (The earlier REVIEW cites only the §2.1 rule; see the last section.) EDLth §5.5 recommends scoring only designated output tokens to avoid the format transient.
- **Hyperparameters.** Not tuned per config in any described way. Table 1: AdamW, b1 0.9, b2 0.999, wd 0.01, constant LR, grad clip 1.0, bf16, "Seeds per config 3". Table 3 (DeepMind Math): LoRA LR 3.53e-4 (1B models) / 1e-4 (3B, 8B); full FT 2e-5 / 2e-6; batch 128, effective batch 1024, 8xH100. Table 4 (Qwen reasoning): LoRA LR 1e-4, batch size 1, effective batch 8, for 1.5B/14B/32B. App. H.1.5 (other tasks): LoRA 1e-4, full FT 2e-5, batch sizes per model. **One LR per (model, method), not per rank** (Table 3 has no rank column). App. H.1.2: they "tested several other optimizers (SGD, Adafactor, AdamW), learning rates and learning rate schedules" and "deliberately report AdamW + constant learning rate". The selection procedure for the LR values is not described.
- **Seeds.** Table 1 says 3 per config. No figure or table in the main text or appendices shows error bars, intervals or per-seed numbers (see Q6).
- **How reported.** Mostly normalised and plotted on log axes: EDL/D vs n (Figs. 2, 3, 4, 5, 8, 9), capacity vs EDL/P (Figs. 3-5), absolute EDL in bits only in the random-label control (Fig. 10: "around 1,000-3,000 bits for arithmetic tasks regardless of dataset size, compared to over 10 million bits with original labels"). Thresholds P* are given as bits/parameter in Tables 6-7.
- **Data order.** App. G: "ensuring that the same examples are seen in the same order by each model during the first epoch" for dataset-size truncations. EDLth §3.1: MDL "depends on the order in which examples are presented".

## Q2. The adapter-size (capacity) threshold

- **EDL_ref.** §2.4 / fn. 2: "we use rank 512 LoRA as a reference, EDL_ref = EDL_{r=512}, which obtains the same performance as full fine-tuning in all of our experiments." Both are computed on the same data D. (Fig. 5's Qwen ranks only go to 256 in the legend; whether the Qwen reference is r256 or r512 is not stated.)
- **Rule for P*.** Table 6 caption: "EDL/P*_EDL is the threshold where EDL/EDL_ref drops below 0.95; EDL/P*_PGR is the threshold where PGR drops below 0.95." Table 7: "EDL/P* at which EDL/EDL_ref = 0.95". So **P\* in the tables is a density in bits per parameter (not a parameter count)**: the value of EDL/P at which the capacity ratio C = EDL(P,D)/EDL_ref(D) falls below 0.95. §5.1 gives the intuition: "The saturation point ... EDL/P*, where PGR drops below 1, corresponds to the maximum learnable information density". Not stated: whether the EDL in EDL/P is the adapter's own EDL or EDL_ref, how the crossing is interpolated, or the uncertainty of the crossing. The dashed lines in Figs. 3-5 are marked without a stated method ("indicated by the knee where saturation occurs").
- **How P is varied.** §3.3: "we use LoRA applied to all layers. We train ranks 1 to 512, including uniformly randomly sampled sparse subsets of parameters within rank 1. Trainable parameter counts range from a single parameter to hundreds of millions". Table 2: rank sweep 1, 2, 4, 8, 16, 32, 64, 128, 256, 512; targets "Q, K, V, O, G, U, D (all layers)"; alpha 32; "Scaling alpha/2r" (as printed; App. G.1.1 "All experiments use the standard scaling alpha/2r, where r is the LoRA rank"); dropout 0; A: Kaiming init with scale 1/sqrt(d_in); B: zero init; "the same learning rate for both A and B". **Nothing further is said about the sparse subsets**: the text has a subsection titled "G.1.1 LoRA and random sparse LoRA training" but its body describes only dense LoRA. Not specified: whether subsets are drawn from A, from B or from both; the sampling unit (individual entries vs rows/columns); how masked entries are frozen (at init, at zero?); whether the subset is fixed across seeds; and the LR used for 10-100 parameter runs. (With B initialised to zero and only A entries trainable, gradients would be zero, so the subsets must include B entries, but the paper does not say.)
- **How P is counted.** Only implicitly: trainable parameters of the adapter; "from a single parameter to hundreds of millions". No formula given.
- **Data regime for the capacity curves.** App. D: "We fine-tune on the full dataset and use LoRA ... for all parameter-controlled experiments"; "for the data-controlled setting, we truncate the training dataset ... and perform full-model fine-tuning". Fig. 3 caption: "Each point compares the fraction of the total performance gap recovered by the specified LoRA rank at a given dataset size", and "Curves for individual LoRA ranks collapse onto each other". So EDL/P is moved by both rank and n. App. I.2 states thresholds need "datasets that are large enough to exceed parameter capacity (larger than ~10K examples, as well as Qwen-R1/s1K Reasoning)".
- **Bits per parameter.** EDL (bits, = nats/ln 2) divided by P. Example of the scale: Fig. 4 spans EDL/P from 1e-4 to ~1.
- **Learning rates per size.** One LR for all ranks (Table 3, Table 4); the alpha/2r scaling is the only rank-dependent factor. App. H.1.2 argues RSLoRA is avoided because it "makes the effective learning rate rank-dependent".
- **Reported values** (Tables 6, 7; no uncertainty given):
  - Llama arithmetic (EDL-based; PGR-based in brackets): 1B add/sub 0.03 (*), mult 0.03 (0.14); 3B add/sub 0.01 (*), mult 0.009 (*); 8B add/sub 0.01 (*), mult 0.004 (*). "*" means PGR >= 0.95 for all sizes tested, so no PGR threshold exists.
  - Pre-elicited Llama 1B mult: 0.07 (EDL) / 0.06 (PGR).
  - TinyStories-1B base: add/sub 2.21 / 2.23; mult 0.70 / 1.02. Pre-taught: format only 1.04 / 0.96 (add/sub), 0.82 / 0.73 (mult); pre-teach mult 0.93 / 1.07 (add/sub), **0.06 / 0.05** (mult); pre-teach add/sub **1.81 / 1.50** (add/sub; checked in the image: the add/sub column of this row is the in-distribution one), 1.48 / 1.56 (mult). Text §5.1 says 1.02 -> 0.05.
  - Table 7: TinyStories-v2 Llama 1B base 0.02, random init 1.2; Alpaca 1B/3B/8B 0.03/0.02/0.02; Qwen2.5 on R1/s1K 1.5B/14B/32B **0.04/0.05/0.02**. §6.3 / §7.3 say "0.02-0.05".
  - Curriculum (App. I.3.2): "capacity thresholds rise (EDL/P* ~ 0.79 bits/parameter)" on problems beyond the pre-taught range.
- **Observation not in the earlier notes:** §6.1 says "larger models have lower capacity thresholds", but that holds only for Llama arithmetic (0.03 -> 0.01 -> 0.01; 0.03 -> 0.009 -> 0.004). For Qwen reasoning the order is 0.04, 0.05, 0.02 (not monotone), and Alpaca is 0.03, 0.02, 0.02. The values are read off figures by eye, so 14B vs 1.5B may be within reading error (method not stated).

## Q3. What the paper trains on

- **Arithmetic** (DeepMind Mathematics, App. B): ground-truth answers ("can also be procedurally generated"). Not any model's output.
- **Pre-teaching** (App. E): permuted/random labels for format, then 4M ground-truth operator-notation examples ("full fine-tuning for a single epoch on 4 million unique examples").
- **Other tasks:** BoolQ, ARC, TinyStories-v2, Alpaca (human/dataset labels).
- **Reasoning (Qwen):** App. D: "R1-generated reasoning traces filtered for accuracy using prompts from the s1K dataset". §3.2: "DeepSeek R1-generated mathematical, scientific, and technical problem solving examples (MATH500, AIME-24, GPQA-Diamond, word games, crossword puzzles)". §6.3: "distillation of DeepSeek R1 into Qwen2.5 14B by fine-tuning on R1-generated reasoning traces". So **the reasoning targets are a stronger, different model's traces, correctness-filtered: distillation with a verifier-style filter, not self-generated.** Also §7.3: "reasoning improvements from distillation operate in the elicitation regime".
- **Own outputs / self-distillation / rejection sampling from the same model:** none. No experiment trains a model on its own samples, and nothing in either paper states a bias correction for on-policy targets.

## Q4. "Minimal information" (Tables 8, 9, 10; App. I.5-I.7)

- **Table 8** columns "1 Example", "10 Params", "100 Params"; metric **PGR** (Eq. 4, §3.4): PGR = (Perf_LoRA - Perf_base) / (Perf_FullFT - Perf_base), "where performance (Perf) is measured by accuracy or loss improvement relative to the model's zero-shot performance". Numbers in parentheses are absolute accuracy gains in percentage points. Performance in Tables 8-10 is **task accuracy** (accuracy; balanced accuracy for BoolQ/ARC), not loss.
- **How the cells are built, as far as stated:**
  - *1 Example:* Table 9 caption "Performance after full fine-tuning on a single randomly sampled example." App. I.6: "fine-tuning on a single randomly sampled example--containing fewer than 10 bits of task-specific information". The example is one random draw (no seed count or selection reported); training length is "to convergence" (fn. 5: "for a single example, this usually occurs after a single training step", said of the pre-elicitation step). Optimizer settings for the single-example runs are not given separately.
  - *10 / 100 Params:* App. I.6: "Training only 10 randomly sampled parameters on the full dataset yields comparable gains: Llama 3.1 8B achieves 91% accuracy (+91 pp) on addition/subtraction with 10 parameters." So these cells use **the full dataset** with 10 or 100 trainable (sparse rank-1) parameters. Sampling details are as in Q2 (unspecified).
  - **The two axes are never crossed:** I found no cell with both a tiny adapter and a single example (or 1-64 examples).
- **Numbers (Table 8; PGR with pp in parentheses):**
  - Llama 3.2 1B add/sub 0.66 (+66) / 0.65 (+65) / 0.71 (+71); mult 0.31 / 0.30 / 0.31.
  - Llama 3.2 3B add/sub 0.86 / 0.87 / 0.89; mult 0.54 / 0.65 / 0.68.
  - Llama 3.1 8B add/sub 0.96 / 0.91 / 0.96; mult 0.67 / 0.76 / 0.81.
  - TinyStories-1B: 0.0 everywhere.
  - Qwen2.5 "Reasoning": 1.5B 0.53 (+7) / 0.14 (+2) / 0.61 (+8); 14B 0.45 (+23) / 0.38 (+19) / 0.55 (+28); 32B **0.55 (+16) / 0.27 (+8) / 0.41 (+12)**.
  - The absolute gains for Qwen reasoning are small (2-28 pp) and rise from 10 to 100 parameters for every Qwen size (PGR 0.14 to 0.61, 0.38 to 0.55, 0.27 to 0.41; the 1-example column is a different intervention, full fine-tuning, so is not on that axis). The Qwen "Reasoning" accuracy metric (which benchmarks, how averaged, which baseline) is not defined in the text; the headline "single-example fine-tuning improves multi-domain reasoning by up to 23 pp (>45% PGR for all Qwen models)" (§6.3) refers to it.
- **Arithmetic zero-shot is 0%** because base models "treat prompts as text to continue rather than questions to answer" (§4.1), so much of the Llama "elicitation" gain is output-format learning plus capability. The authors acknowledge this (App. I.7: "this reflects the models' inability to follow instructions and produce correctly formatted responses") and the pre-elicitation experiments (App. E.1.1) separate format.
- **Table 10:** base + 1 example beats the instruct model's zero-shot on arithmetic for all Llama sizes (n* = 1). On BoolQ/ARC the 1-example base is below or near IT (n* from 1 to 8). Table 11 (16-shot prompting) is the behavioural cross-check: Llama add/sub 29.0/58.9/67.7 %, TinyStories 0.
- **Information content claims:** "approximately 3-7 bits of answer information (log2 of the answer space)" per arithmetic example (App. I.6); "Llama 3.1 8B achieves 96% accuracy ... after fine-tuning on a single randomly sampled example (~8 bits)" (§6.1). EDLth §5.2/B.2: a single diagnostic example "can contribute at most min(log|Y|, log m) bits to EDL" and EDL <= MDL; so a one-example EDL is bounded by that example's code length under theta_0.

## Q5. Elicitation-versus-teaching criteria and their limits

- **EDL-per-token shape** (§4, App. J.1): elicitation: "EDL per token is low and decreases monotonically as dataset size increases"; teaching: "EDL per token enters a phase of increasing returns as data scale ... followed by a subsequent crossover to diminishing returns". Formal (App. J.1): elicitation predominates when d/dn [EDL(n)/n] < 0, teaching when > 0. §4: "these signatures characterize which process dominates, not a strict dichotomy."
- **Capacity thresholds:** elicitation 0.01-0.1 bits/param "or fewer" (§1 bullet; §6.2), teaching "roughly 1 bit per parameter or more". §6.4 practical guidance: pilot with high-rank LoRA at target n, classify by EDL scaling, choose adapter so that EDL/P is "<0.1 bit/parameter for elicitation, ~1+ bit/parameter for teaching". Table values range 0.004-0.14 for elicitation and 0.70-2.23 for teaching (Q2).
- **Limits on transfer (stated):** §7.4: "As EDL depends on the training algorithm, different training techniques, optimizers, learning rates, or other hyperparameters could yield different values"; "Our experiments focus primarily on arithmetic and reasoning tasks for which high-quality training corpora are widely available and performance can be scored against verifiable ground truth solutions; other capabilities may behave differently. We study primarily Llama and Qwen families of dense transformer models; other architectures, such as Mixture-of-Experts (MoE), may have different capacity characteristics." App. J.4: thresholds "mark where learning efficiency drops ... not where learning stops entirely", and with finite compute a low P* can mean "efficient learning that continues" or "inefficient learning that stalls"; "We report absolute performance alongside capacity metrics throughout to distinguish these cases." App. H.1.2: hyperparameter choices "primarily affect the low-data, low-parameter regime of single-epoch training". §6.1: "larger models have lower capacity thresholds (when architecture/pretraining is fixed)". The paper says nothing about OLMo, thinking-trained models, 32B Llama-style models, or data scales between 64 and 1,000 for LoRA capacity (Qwen reasoning went 10-1,000 examples, Fig. 5).
- **Signature needs a scaling curve.** Teaching peaks occur at ~1K (language), ~150-300K (arithmetic) and >4M (mult) examples (Table 5), so a single small n cannot reveal a later rise. Llama itself "cross over to teaching-dominated signatures when trained on millions of examples" (§4.3).
- **Capacity is only measured when the data exceed capacity.** App. I.2: the P* values come from datasets "larger than ~10K examples, as well as Qwen-R1/s1K Reasoning". At small n, many ranks are all at C ~ 1 (the "*" entries).
- **RL:** no RL experiment in either paper. BTC §7.3: "This also has implications for assessing whether other post-training techniques, such as compute-heavy RLHF, primarily elicit existing capability or teach new skills. ... This suggests that RLHF, while computationally expensive, may be largely elicitation." This is an inference from SFT results (single-example SFT beating the RLHF'd instruct models on arithmetic). §7.5 cites single-example RL (Wang et al. 2025) and random rewards (Shao et al. 2025) as consistent but does not test them. EDLth §7.2: "Third, our analysis focuses on supervised fine-tuning. Extensions to reinforcement learning, preference optimization, and other post-training methods require additional development." EDLth App. D.2 says maximum EDL is "particularly relevant for ... fine-tuning, reinforcement learning, or other post-training methods" but gives no RL method.
- **MDL alone:** §7.5: "repeating our analyses with MDL instead of EDL failed to reliably distinguish elicitation from teaching, whereas EDL was discriminative in all configurations tested" (no numbers given).
- **Independent validation:** few-shot prompting (App. I.9, Table 11) and logit-bias correction for multiple choice; "We regard a model as capable of being elicited on a particular task if multi-shot prompting or removing biases ... results in significantly improved performance" (App. D).
- **Controls:** random labels give EDL ~0 (App. I.10, Fig. 10; EDLth Prop. 5.1); out-of-distribution pre-teaching (add/sub pre-teaching does not convert mult; Table 6).

## Q6. Error bars and seeds

- Table 1 says "Seeds per config 3". **No table or figure reports a standard deviation, interval, or per-seed value** in either the main text or the appendices that I read; Figs. 2-5, 8-10 are scatter/line plots with no visible bars (checked Figs. 4-5 visually). Tables 5-11 are single numbers.
- Therefore **none** of: P* values (Tables 6-7), PGR (Tables 8-9), few-shot accuracies (Table 11), EDL scaling signatures (Table 5 is qualitative arrows) has stated uncertainty. Threshold crossings are read from plots.
- EDLth §6.1 recommends reporting "confidence intervals or variance estimates alongside EDL measurements, particularly for small datasets where variance may be substantial" and App. C.1 gives Var[EDL] = O(n) (proof sketch; "Under mild regularity conditions"); BTC does not say it did this.
- The 1-example numbers in Tables 8-9 are described as one "randomly sampled" example; how many draws/seeds underlie the table entry is not stated.

## Q7. What bears on our design questions

(a) **Training on the model's own verifier-selected samples.** Not covered empirically (Q3). Theory: EDL = MDL - n * L_test requires i.i.d. (x, y) from a fixed distribution (EDLth §2.1 and Thm 4.2: "Let D be drawn i.i.d. from distribution D"); with targets sampled from the model itself the first-epoch loss is already low (the earlier note's concern), and the papers neither address nor correct this. The closest in-scope case is a different model's correctness-filtered traces (R1 on s1K prompts). Also: "EDL measures learning as data compression achieved through generalization, not semantic content or performance" (BTC §7.4), and EDL "depends on the training algorithm".
(b) **Targets with a long thinking segment.** Qwen runs score "the full response including chain-of-thought reasoning final answer" (App. F). Batch size 1 / effective 8 (Table 4), n from 10 to 1,000 (Fig. 5), LoRA ranks 1-256 (Fig. 5 legend). R1 traces are typically long but the paper gives no token lengths. The format-transient argument (EDLth §5.5) says whole-response scoring can confound format and capability, and for arithmetic they mask format; for reasoning they chose not to separate thinking from answer.
(c) **Single pass vs multi-epoch.** The design is explicit: MDL from epoch 1 only, residual from the converged model, "multi-epoch training should find the minimum regardless of hyperparameters" if a small set can elicit (App. H.1.2). The same paragraph warns the hyperparameters matter in "the low-data, low-parameter regime of single-epoch training". EDLth Prop. 4.9: EDL differs across algorithms in general; "the algorithm should be held fixed or explicitly varied". EDLth App. D.2: "While EDL can be computed at any point(s) in training, it is especially powerful for estimating the maximum amount of generalizable information a model can extract from a finite dataset given unbounded compute." The number of epochs used is not reported, and for n = 1 a single step suffices to converge (fn. 5).
(d) **Small n.** The only small-n results are accuracies for n = 1 (Tables 8-10; n* = 1 to 8 for beating the IT model) and Qwen reasoning at n = 10-1,000 (Fig. 5 inset: EDL/D falls from ~0.2 to ~0.03 over that range). The paper gives no EDL value for n = 1-64 in a table. EDLth Prop. C.1: relative uncertainty of EDL/n is O(1/sqrt(n)), so small-n EDL is noisy. A one-example EDL is at most that example's code length under the start model (EDLth §5.2, B.2).

## Where our earlier notes were wrong or incomplete

Checked against: `docs/literature/2026-11-25-elicitation-metrics/notes/donoway2026-bits-that-count.md`, that folder's `REVIEW.md` (item 1 and R1, plus the weaknesses section), and `docs/literature/2026-10-02-lit-review-2/notes/donoway2026-edl.md`.

1. **Loss mask for reasoning (REVIEW weakness 4, and the BTC note).** They quote §2.1 ("designated label tokens, typically the answer portion") as if it applied to our thinking-heavy targets. App. F says the Qwen reasoning runs score "the full response including chain-of-thought reasoning final answer". So the paper's reasoning thresholds (0.04/0.05/0.02) include thinking tokens; our whole-response EDL is in line with that, and masking to the answer would be a departure, not the paper's convention.
2. **"Sparse subsets" are under-specified, not just quoted.** REVIEW R1 reuses the §3.3 phrase as "as Bits That Count does". The paper never says which entries of A/B are trainable, how frozen entries are set, or how the subset is sampled, so `S_hi`/`S_lo` cannot be a replication; they are our own construction.
3. **10- and 100-parameter cells use the full dataset; 1-example cells are full fine-tuning.** The notes list Table 8's three columns together under "minimal information". Tiny adapter x tiny data was never run in the paper. The BTC note's "One example, 10 parameters or 100 parameters give PGR of ..." is accurate as a list but could be read as one condition.
4. **P\* is a density, with no stated uncertainty and eyeballed crossings.** The notes give the 0.95 rule correctly, but do not say the numerator EDL is ambiguous (adapter vs reference), that the crossing is read off dashed lines, and that no interval is given. BTC note says "reports no per-example noise ... beyond 3 seeds"; in fact **no seed-level numbers or error bars appear anywhere** (Q6).
5. **One LR per model across ranks.** REVIEW R1 plans per-arm LR grids ("Bias and sparse adapters need larger rates"). The paper used one LR per (model, method) for all ranks 1-512 (Tables 3-4), with alpha/2r scaling, and did not report sparse-subset LRs. A per-arm grid is a sensible departure but is not the paper's protocol.
6. **"Larger models have lower thresholds"** is repeated in the notes; it holds for Llama arithmetic only (Q2). For Qwen reasoning, the model family closest to our setting, it is 0.04, 0.05, 0.02.
7. **Qwen reference rank.** REVIEW says the reference is r512 "in all experiments" (fn. 2); Fig. 5's Qwen rank legend stops at 256, so the reasoning capacity curve may be referenced to r256 (unstated).
8. **Qwen minimal-information numbers are weak evidence.** REVIEW and the BTC note quote PGR 0.55/0.27/0.41 for 32B; the absolute gains are +16/+8/+12 pp, the 1-example column is a different intervention from the 10/100-parameter ones, and the metric is undefined in the text. They support "a few parameters or one example move the number", not a clean capacity law.
9. **Theory-paper note (2026-10-02) covers v1 correctly**, but its remark that the empirical claims are "UNVERIFIED" is now resolved by BTC; its worry that self-generated targets bias the prequential code is **not addressed by either paper** (they neither test nor discuss it), so it remains our own open issue.
