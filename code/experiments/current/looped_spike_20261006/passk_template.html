One panel per model, one line per test-time loop count. If loops bought proofs, the lines for more loops would sit clearly above the lines for fewer. Mostly they don't: beyond about 4 loops, or any number of thoughts, the lines lie on top of each other, and moving right along a line (more samples) gains far more than moving between lines.

Read with care

  • One seed per model. Curves are exact expectations over subsets of the samples drawn (64 per problem on long dev, 256 on textbook72, 128 on RL unsolved), so they are smooth, but a different seed would move a whole panel by a few problems.
  • Each chart draws five budgets; the strip under it gives the solved count for every budget measured.
  • "RL unsolved" is each model's own set of RL targets that none of its rounds solved, so its size differs by model and it is plotted as a share. It was chosen by failing at the budget RL sampled with (2 loops, or 8 thoughts), which favours other budgets a little.
  • These are Tuesday night's models, trained with the old 4-round RL. The autoresearch loop's later models were scored only at 2 and 8 loops (best: 766 against 739 of 1,108 dev theorems), so they have no curves here. Run 198 with the improved RL scores 792.
  • With the x-axis on compute, each looped line is stretched by its cost per sample (2 + 2n blocks against run 198's 6), so lines at the same x have spent the same compute. Thoughts add a few positions per sample and are not rescaled.
Pools: long dev = the 329 dev theorems whose reference proof has 10 or more lines; textbook72 = 72 textbook problems. Sampling temperature 0.8, as in the harness. Built from loop_sweep_*.json and thought_sweep_final.json; code in code/experiments/current/looped_spike_20261006/passk_page.py.
