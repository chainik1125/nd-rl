# Scope of the sprint relative to the proposal

This is a bounded implementation of the three questions in the [proposal](../../../../proposals/learned-compute-allocation/README.md), using Dan's 9.56-million-parameter round-16 proof-state model. It is not a complete hyperparameter study or evidence about frontier language models. The [frozen allocation method](allocation/main_method.md), [selection method](selection/method_freeze.md), and [causal test plan](context/causal_test_plan.md) specify the actual experiments.

The cost-aware training arm uses one nonzero cost, 0.03 per additional attempt, with three independent RL seeds. The correctness-only arm has the same three seeds. Costs 0.01 and 0.1 are evaluation utilities and staged-policy calibration settings, not separately trained joint-RL conditions. Each joint run has 200 updates of eight episodes. The implementation uses one on-policy gradient update with an episode-level leave-one-out baseline and gradient-norm clipping; it does not run repeated PPO epochs or claim a reproduced PPO implementation. Checkpoints 100 and 200 compete on a 32-theorem development panel. These choices leave substantial optimization uncertainty after a negative result.

The primary frozen-generator selection experiment uses eight independent proofs per theorem. Its pooled chooser is trained to select any valid proof. Separately declared controls include factorized selection, binary validity critics, public-feature scoring, and a scalar head on frozen original representations. Confidence thresholds are explicit policies calibrated on development data. They test adaptive allocation from learned correctness estimates, while joint RL tests a single trainable generator/controller. These are different claims.

The fresh main evaluation holds out canonical and atom-erased formula-skeleton groups and excludes audited historical exposures. It does not hold out the underlying proof-program families. Disjunction-elimination tasks share a construction, and some forward problems have inconsistent premises or goals with simple implication introductions. Good performance on this distribution is not unrestricted theorem proving. The reused 72-theorem benchmark is reported separately as historical retention/transfer; source role names do not establish actual exposure in the chosen checkpoint's training stream.

Sequential generation required outcome-blind interface adaptation because merely adding attempt-history markers broke the original generator. The chosen format adapter trains on 0/1/4 prior frozen-generator proofs; live deployment can contain seven student-generated proofs. Its first-attempt retention is acceptable on development, but later generation still degrades. The sequential context allowance also extends the original nominal 1,024-token setting. This interface and distribution mismatch constrains what a failed joint-RL trial says about learned computation in general.

All earlier proofs remain selectable. Native categorical selection, greedy selection, and oracle availability are separate measurements. A loss under stochastic selection can disappear when a greedy rule always returns the first proof; that behavior still does not establish useful selection of additional attempts. Forced continuation states need not be states the learned policy would naturally visit.

The primary continuation intervention generates one additional proof and then selects; the proposal's force-one-then-resume-the-learned-policy estimand is a registered secondary measurement, alongside two- and four-forced-attempt continuations. The memoryless-generation control removes prior-proof context from future generation while preserving old candidates for the chooser. Because it changes future proofs, it does not isolate history's direct effect on recognition or acceptance. The sprint does not run the proposed fixed-candidate-pool intervention with additional nonselectable history or filler, compact-history control, length/count transfer to 16 attempts, or a held-out test of entropy's incremental predictive value beyond simpler state covariates.

Negative average continuation value establishes harm for the measured continuation and selection policy. It does not establish that the acceptance rule recognizes harmful states. That stronger claim requires acceptance to discriminate continuation value within relevant state strata and to improve on appropriate count, length, and confidence controls. The sprint tests selection and allocation ingredients of the proposed meta-learning setup; it does not by itself establish a general ability to adapt reasoning strategies to new task families.

Joint-RL runs share a maximum number of episodes, not total generated attempts or training compute. Their1600 episodes sample the1600-theorem corpus with replacement: primary seeds101/102/103 see1002/987/1013 distinct theorems, with identical update/slot schedules across cost conditions. The three-seed union covers1520 training theorems. Development can select different checkpoint ages: fixed-one chooses update100, representing800 episodes and622 distinct theorems, while the other selected policies use update200. All runs nevertheless completed200 updates, whose full cost is reported. Inference comparisons likewise distinguish expected policy work from the larger expense of measuring every forced path. Staged stopping is evaluated by exact averaging over orders of saved independent eight-attempt pools; its mean attempts and work describe the simulated online policy, not measured wall-time savings from an online early-exit service. Frozen-pool work estimates are logical unpadded input-token lower bounds; live-path measurements count actual model input forwards under that implementation. Their numerical scales should not be merged into a single cross-system compute frontier. Neither is end-to-end deployment latency.

Theorem-bootstrap intervals condition on the fitted checkpoints and saved generation draws. Report each training seed as well as the mean. Single-seed fixed-budget controls cannot establish robustness to control-training randomness. Development results explain design decisions; only the frozen final evaluation can support held-out comparisons, and all prespecified unfavorable results remain in the report.
