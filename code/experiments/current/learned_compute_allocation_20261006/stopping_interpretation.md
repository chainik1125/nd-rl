# What a learned stopping decision must establish

The practical objective is correctness of the proof the system returns, charged for the work needed to generate and select it. Oracle pass@k measures whether a correct proof exists in a pool. It does not establish that the model can recognize that proof or decide that further sampling is unnecessary.

Let a state contain the original theorem and every retained attempt. Write `V_accept(s)` for expected correctness under the current selection policy, and `V_continue(s)` for expected correctness after a specified continuation policy and its final selection. With a cost for additional work, continuing is useful when the expected gain exceeds that cost. The sprint's one-extra and resumed-policy interventions estimate different versions of this difference. The latter includes the trained policy's subsequent stopping decisions; neither can be substituted silently for the other.

Keeping earlier candidates makes oracle availability nondecreasing. With unrestricted access to the previous selection rule, a policy can also ignore new evidence and return the same earlier proof. Thus a correctness-only policy's observed early stopping is not by itself evidence that additional reasoning is intrinsically harmful. A bounded learned selector can redistribute probability toward invalid candidates, or a fragile history interface can degrade its later generations. Both can make stopping rational for that particular trained system without establishing a broadly useful metacognitive skill.

The causal analysis therefore decomposes final correctness into probability assigned to valid old proofs and valid new proofs. A net loss while old valid proofs remain available is a failure of the current selection policy. The mass decomposition does not by itself show that the model's representation of those proofs deteriorated: normalization and sampling across an expanded candidate set can also dilute probability on a good candidate. Low validity of new attempts is a generation limitation. Monotone oracle availability alongside falling selected accuracy exposes the policy gap directly. Removing generator history while retaining the chooser's candidate set helps distinguish these mechanisms, while changing the generator's information and input distribution simultaneously.

The native causal readout integrates the trained categorical index distribution. A greedy index rule may remove stochastic loss by repeatedly choosing the first proof. Such a rule can avoid that loss without learning to benefit from new attempts. Native and greedy deployment therefore require separate reporting; a negative categorical continuation effect is not a claim that every deployment rule must deteriorate.

A calibrated per-proof critic offers a simpler staged approach: score each newly generated proof, retain the highest-scoring proof, stop above a development-calibrated threshold, and otherwise sample again up to a budget. The threshold is an explicit decision rule over a learned correctness signal. It is not evidence that a single model learned the entire generation-and-allocation policy through reinforcement learning. Binary cross-entropy does not guarantee calibration after maximum selection or distribution shift; held-out deployment measurements remain necessary.

The frozen-backbone scalar critic tests a useful engineering separation. It preserves the generator parameters exactly while learning a small recognition readout from existing representations. The held-out head reaches84.0% overall, close in point estimate to its matched full critic, but reaches83.58% on the67 all-complete mixed-validity pools versus89.55% for that critic and95.52% for public features. This descriptive stratum limits a claim of equivalent recognition. Its385 trained parameters do not remove the backbone inference needed to score each proof. A next training stage could teach continuation value while protecting generation, using the staged system as a baseline. This is a proposed direction, not a result of joint meta-learning in the present sprint.

For that next stage, reserve independent stopping-training pools or cross-fit the critic before fitting a stopping policy. Training a policy only on the critic's in-sample predictions can give it an unrealistically clean confidence distribution. The [reviewer's proposed minimal follow-up](reviews/next_stopping_experiment_judgment.md) uses count and incumbent score with a small count-dependent threshold schedule, compared against a constant threshold and fixed mixtures. It is deferred from this sprint's final-test registry.

The constant-threshold control is substantive. Under known iid future payoffs, reliable observed incumbent value, full recall, and constant positive sampling cost, the optimal reservation threshold is independent of the remaining finite horizon, except at compulsory termination. The [follow-up design](selection/followup_stopping_design.md#policy-optimization-and-controls) gives the short argument. A genuine expected-value gain from count dependence would therefore reflect departures from that idealization, such as theorem-dependent continuation value or imperfect confidence, rather than finite horizon alone. An apparent finite-sample gain can also reflect noise or optimization error. We have not established those idealized assumptions empirically.

An online follow-up should also validate extracting the feature baseline's likelihood and entropy statistics directly during cached generation. The current predictor is fitted and evaluated using an additional full replay pass, which this sprint charges. A [small development check](selection/cached_confidence_note.md) found nonidentical statistics but unchanged fixed-eight choices in 16 pools and unchanged threshold crossings for all 128 candidates; maximum scorer-probability change was 0.00328. This finite-panel agreement does not establish general numerical or decision equivalence. Runtime matmul precision flags and per-token cached logits were not retained, and instrumented timing is unsuitable for speedup claims. Broader validation or newly calibrated training/development features are needed before replacing the replay; no online latency saving is established here.

Three comparisons carry the interpretation: selected accuracy against strong same-pool recognition baselines; learned stopping against count-only and fixed-budget rules using the same checkpoint; and separately trained fixed-one/fixed-four controls. Every training run has the same maximum update and episode budget, but development selection can choose different checkpoint ages. Sampled attempts and training computation are also unequal. Report both the completed training expense and the updates represented by the selected checkpoint.
