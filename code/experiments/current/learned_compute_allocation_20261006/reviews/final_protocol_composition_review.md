# Decision parent, public seal, and registered causal launch

The two-phase composition preserves the intended information boundary. A parent freezes all nine resolved live choices, fitted policies, selection/analysis entries, collection commands and source identities before independent test-pool generation. The collection wrapper sends outcome-bearing stdout/stderr to an unread private log. Renderer and sealer consume only public candidate records and planned metadata. Finalization deep-copies the frozen decisions, adds public-view hashes and provenance, changes status, and binds the historical registry to the finalized MAIN registry hash.

The strengthened model validator requires model/config/inference identities and nonempty primary fit paths/hashes. Seal validation checks the original parent, exact commands and order, successful exit codes, registered collection-launcher hash, unread-outcome flags, expected metadata and unchanged public bytes. The causal launcher binds its own source, verifies all four conditions for the selected checkpoint before optional condition filtering, and rechecks registry/inventory immutability before each job. The actual evaluator/analyzer retain their own registration gates.
