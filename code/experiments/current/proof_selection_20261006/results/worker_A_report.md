## Bottom line

- **H1, as pre-registered, is not supported.** At k=8, the learned verifier ensemble (`verifier_ens`) selects a valid
  proof less often than the intrinsic `completion_loglik` scorer on both test sets. The paired gap is
  completion_loglik − verifier_ens = **+0.012 [+0.001, +0.022]** on holdout250 and **+0.025 [+0.010, +0.044]** on
  textbook72. Each of the 3 seeds is also below completion_loglik, with every paired CI excluding 0. The supervised
  shallow baseline `shallow_lr` sits between the two, and neither of its gaps is resolved.
- **The reason is visible on dev, before any test read.** The verifier head has the *highest pooled* AUROC of all
  scorers (test: 0.92–0.97), but among finished attempts of the *same* theorem it ranks valid above invalid poorly:
  within-theorem AUROC is 0.60–0.65, against 0.69–0.79 for loglik. Pooled BCE training learned *which theorems are hard*,
  not *which of this theorem's proofs is wrong*. Selection needs only the second. (Figure `figures/A_pooled_vs_within_auroc.png`.)
- Two dev-motivated fixes did not change this. The first was a history input format that removes the brief's
  heavy clipping. The second was a within-theorem ranking loss with within-theorem early stopping. Both were decided
  and frozen before the test read; neither recovered the gap.
- The best k=8 selectors recover about 77–79% (holdout250) and 71–73% (textbook72) of the oracle − random gap. These are
  completion_loglik and completion_entropy, which are Worker B's intrinsic scorers.

## Verifier details

- Model: the r16 checkpoint (`load_ckpt`, Peri-LN/ALiBi 6×384) plus a zero-initialised linear head on the final
  token's hidden state after `ln_f`. BCE with pos_weight = n_neg/n_pos (0.134), so nothing is dropped. AdamW (body
  1e-4, head 1e-3, wd 0.01), cosine schedule, 65,536-token batches, at most 3 epochs. Every 300 steps it is evaluated
  on the selector-dev split (11,072 attempts) and the best checkpoint is kept, with patience 6.
- Train split: 97,776 attempts (88.2% valid). There are only **3,195 finished-invalid attempts**, spread over 1,227
  theorems that have both a finished-valid and a finished-invalid attempt. That is a small budget for learning
  "wrong term" detection.
- **Brief's input format (primary, `verifier_s*`).** The input is `[state_1 action_1 eos state_2 …]`, where actions
  are the environment-effective (env-renamed) tokens, matching SN training. It is clipped to 1024 tokens by dropping
  the earliest pairs, which clips 77% / 80% / 93% / 81% / 57% of attempts in rl_targets / dev1108 / rr600 /
  holdout250 / textbook72. Clipping hides the early actions, and those actions are where wrong terms sit.
- **Secondary `verifier_hist_*`** (decided at 02:09 from the clip rates alone, before any verifier result). The input
  is Dan's arm-SH input for the last step: all earlier effective actions + the final state + the final action. It
  clips only 0.3–2.0% of attempts. Its pooled AUROC is higher and its within-theorem ranking is no better.
- Clipping-stratified check (audit item 8): among holdout250 finished attempts, verifier_ens AUROC is 0.717 on
  clipped and 0.800 on unclipped attempts. On textbook72 it is 0.756 vs 0.633, so the direction is inconsistent across sets.
  The rarely-clipped hist head gives 0.772 / 0.775 (holdout250) and 0.805 / 0.727 (textbook72) and still does not win
  selection. Clipping is therefore not the main reason
  the head loses.
- **Secondary `verifier_hist_rank_s0`** (decided at 03:17 from dev). It uses whole-theorem batches, the loss 0.5·BCE
  + pairwise logistic loss over (finished valid, finished invalid) pairs within a theorem, and early stopping on dev
  within-theorem finished AUROC. Best dev value 0.665, against 0.60–0.67 for the BCE heads. Under the rule set
  beforehand, seeds 1–2 were not run.

## Overlap and split guarantees

- Exact prompt, name, and Dan's renaming-class `key`: 0 overlap between all 10 set pairs (textbook72 has no `key`).
- Atom renaming + premise permutation key, applied to all five sets: one collision, rl_targets line 2229 = dev1108
  line 150, which was forced into train. There are 0 keys shared between any train/dev source and holdout250 or
  textbook72, and 0 within-set duplicates.
- **Not guaranteed:** structural/schema families. The 19 textbook schemata appear in rl_targets (760), dev1108 (366)
  and holdout250 (90) with different sub-formulas. In addition, 14/72 textbook72 theorems have `role: rl_train` (the
  *generator* saw them during EI; the selector did not). The test sets were also design-visible beforehand through the
  prior headroom table (audit item 7). The pools are fresh attempts, not fresh theorems.

## Limitations

1. **One generator seed, one pool draw per set.** Selector uncertainty comes from 3 head seeds plus a theorem
   bootstrap. The R=200 subsets reuse the same k attempts, so they are not independent evidence.
2. **Small test sets.** textbook72 has 72 theorems, 22 of them unsolvable at k=64, so its CIs are wide (±0.10).
3. The pre-registered `shallow_lr` uses Worker B's loglik_mean / entropy_mean as features, so it inherits their
   masking choices. `completion_loglik` is also Worker B's scorer; its correctness rests on B's replay and masking
   checks, not mine.
4. **Few hard negatives for training** (3,195 finished-invalid attempts). A head trained on many more hard negatives,
   or on pools from harder theorems, might rank within a theorem better. This sprint does not test that.
5. "completion" uses the environment's syntactic checks (scope, goal match, binder formulas; audit item 4). It is a
   partial verifier in its own right, and all scorers get the same access to it.
6. The test evaluation used the full frozen scorer list (27 scorers). Only the 02:08 primary comparison is
   confirmatory; the rest are secondary. The best-looking secondary (completion_entropy at k=64 on holdout250) was
   not chosen in advance.
7. Early stopping did not converge uniformly. hist_s0's best checkpoint is its final step (1791; dev AUROC was still
   rising at the 3-epoch cap), while hist_s1/s2 peaked at step 600, so hist_s0 may be undertrained.
8. Lean judging used `lean_judge.judge_many` (nd2lean translation) rather than Dan's in-loop literal-text gate. Dan
   documents the two as equivalent; I did not recheck that.
