# Proposal 22: MCTS with a learned value for the cap-12 model organism

## Question and view

Dan (2026-10-02): "I feel like MCTS should improve the model … We may need to add some kind of GRPO or PPO thing on top
of EI."

**My view.** MCTS should help this model, and most where RL has stalled, but only with a learned value. The policy
update needs no GRPO or PPO.

1. **Where search should help.** In `trajectory`, proofs RL completes had one improbable step, about −6 nats after
   pretraining. The theorems RL never solves (group C) have **two or more** hard steps: reference worst step about
   −9 to −12 nats, and 55–86 % have a second step below −4.
   - Independent sampling needs every hard step right in one attempt, so its success *multiplies* their
     probabilities.
   - Tree search can resample at the hard state without redoing the prefix, and find each hard step separately.
     The cost is then closer to the *sum*, provided the search can tell a partial proof is on track.
   - That signal is the value.
2. **The value is the crux.**
   - Our best-first search expert (`search-expert`) had no value. It spent about ¼ of sampling's budget and taught
     the apprentice no more than sampling did.
   - In HTPS (2205.11491v1, Table 5), a soft critic gave 78.1, no critic 65.6, and a hard (badly trained) critic
     63.1. A bad value is worse than none.
   - AlphaProof's value predicts negative steps-to-go, with Q = γ^{−V−1} (Methods, checked 2026-10-02).
3. **No GRPO or PPO needed.** AlphaZero trains the policy toward the search's **visit distribution** and regresses
   the value on outcomes. AlphaProof trains on (state, tactic) pairs from **found proofs and disproofs**, with
   cross-entropy. Both are expert iteration with search as the expert.
   - Training toward visit distributions also gives a signal from searches that **do not** finish. That answers
     the near-miss gap in our EI, which ignores failed attempts.
   - `grpo-best` tests policy gradients separately. Mixing the two here would make both harder to read.

## Design

**Model:** `trajectory`'s three cap-12 seeds (Robbie's recipe, 9.56M, proof-state environment, `lean_staten`).
`trajectory`'s per-theorem groups (A, B, C) and read-outs are the baselines.

**Phase 0, build (one executor session):**
- **PUCT search** over proof states:
  - prior π^{1/τ};
  - an exploration factor that grows with visits (AlphaProof's c(s));
  - K actions sampled per expansion, deduplicated by resulting state;
  - **progressive sampling** (K more at nodes where n(s) ≤ C·N(s)^α).
  - The environment already rejects invalid steps, and Lean decides complete proofs.
- **Batching across many trees,** so the GPU stays busy. This is where `search-expert` lost most of its budget.
- **A value head** on the policy trunk: steps-to-go (AlphaProof's target, γ-discounted), plus a "solvable" logit.
  - Train it **first with the trunk frozen**, so the policy is unchanged and Phase A can attribute any gain to
    search.
  - Training data comes from rollouts on `rl_targets` and the generator pool, **never the evaluation pools**:
    states on accepted proofs get their true steps-to-go; states on failed attempts get "unsolved".

**Phase A, test-time search** (no policy training; cheap; decides whether Phase B is worth it). Compare at equal
GPU-seconds, using the `compute-record` rows:
- plain sampling at k 256 (the `trajectory` read-out);
- PUCT **without** the value (prior and progressive sampling only), which is proposal 20's E1;
- PUCT **with** the value.

Run this on textbook72, holdout250, **group C** and the long pools, from both `trajectory`'s end-of-pretraining and r8
checkpoints.
- **Prediction:** PUCT with the value solves a substantial share of group C; without the value, little more than
  sampling.
- **Falsifier:** at matched GPU time, PUCT with the value solves no more of group C than sampling does.

**Phase B, MCTS as the RL expert** (only if Phase A passes). Run 8 rounds from the end-of-pretraining checkpoints
(3 seeds), with the same targets, replay and fine-tune steps as `trajectory`'s ladders, and GPU-seconds matched to
them (fewer, deeper searches per round).
- **B1:** train on **found proofs**, the shortest per theorem (AlphaProof-style).
- **B2:** train toward **visit distributions** (AlphaZero-style), including searches that did not finish.
- The value is retrained each round in both arms.
- **The apprentice is evaluated two ways:**
  - **without search** (plain sampling), against `trajectory`'s EI. This asks whether search taught the policy
    something.
  - **with search.** This is the best system number, against Robbie's combined model and `best-state`.

## Read-outs

- **Group C** solved, for each arm and seed (the headline), by plain sampling and with search.
- pass@k by `trajectory` group; the textbook72 and holdout250 totals.
- Value calibration: predicted against actual steps-to-go, on held-out targets.
- Search statistics: nodes per proof, and how deep the hard steps sit in the tree.
- Compute per arm.

## Cost

- **Phase 0:** one heavy coding session; pods ≈ $2 for value-head data and training.
- **Phase A:** ≈ $8–12.
- **Phase B:** ≈ $35–45 (6 searched ladders at matched GPU time, plus read-outs).
- **Total ≈ $50–60.** Phase B runs only if Phase A passes, so the committed cost up front is ≈ $15.
